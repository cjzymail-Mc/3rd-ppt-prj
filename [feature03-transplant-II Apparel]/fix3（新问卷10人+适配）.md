## 2. 5 项具体改动

### 2.1 扩展 `_classify_columns` 签名（`src/_ppt_shared.py`）

加可选参数 `extra_skip_keywords`，融入现有 `skip_cols` 集合。yzr/zxh 不受影响（默认 None）。

```python
def _classify_columns(headers: List[str], rows: List[List[Any]],
                      extra_skip_keywords: Optional[List[str]] = None,
                      ) -> Tuple[List[str], List[str]]:
    name_col = _find_col(headers, _NAME_KEYWORDS)
    weight_col = _find_col(headers, _WEIGHT_KEYWORDS)
    extra = list(extra_skip_keywords or [])
    skip_cols = {name_col, weight_col} | {
        h for h in headers
        if any(kw in h for kw in (_SKIP_KEYWORDS + extra))
    }
    # ... 其余逻辑不变
```

### 2.2 apparel 本地 SKIP 列表（`src/apparel_ppt.py`）

新增模块级常量：

```python
# 新问卷新增维度 + 元数据列，避免被 _classify_columns 当成文本反馈列
# 污染 GPT prompt。展示需求由后续 fix 处理。
_APPAREL_SKIP_KEYWORDS = [
    "三围", "温度", "场景", "支撑", "跑量",
    "data_id", "提交", "更新", "标题", "品牌", "试穿产品",
]
```

`_build_respondent_block` 调 `_classify_columns` 时传入：

```python
score_cols, text_cols = _classify_columns(
    headers, rows, extra_skip_keywords=_APPAREL_SKIP_KEYWORDS,
)
```

**注意**：`_build_rich_prompt` 内的 `respondent_block` 也走这条路径，所以优点/缺点的 prompt 一并去污染。

**调用关系澄清**（避免下个 maintainer 误改）：
- `_build_rich_prompt` → `_build_respondent_block` → `_classify_columns`（**需要传 skip**）
- `_build_respondent_info_prompt`（TextBox 24 专用）**不走** `_classify_columns`，
  手动按 _NAME/_WEIGHT/身高 keywords 抓取，无污染问题，无需传 skip。

### 2.3 TextBox 24 budget 按 n 动态化（`src/apparel_ppt.py:_build_content`）

`gpt_respondent_info` 分支前，根据 rows 算 n，覆盖 budget：

```python
if strategy == "gpt_respondent_info":
    n = max(0, len(rows) - 1)
    # 动态 budget：标题 1 行 + 每名 1 行
    budget = dict(budget)  # 不修改 SHAPES 里的原 dict
    budget["max_lines"] = max(budget.get("max_lines", 5), n + 1)
    budget["max_chars"] = max(budget.get("max_chars", 102), n * 22)
    # ... 后续 style_anchor / fallback / prompt 不变
```

`_build_respondent_info_prompt` 内 prompt 文本 "接下来每行一名测试者" 已经是 1 行 1 人格式，无需改。

### 2.4 TextBox 24 shape Height 拉长（`src/apparel_ppt.py:make_apparel_slide`）

写完 TextBox 24 文本后，按基线（6 行=1 标题+5 人）线性扩展 Height：

```python
# 在 _write_text(shp, content) 调用成功后
if name == "TextBox 24" and ok:
    n_samples = max(0, len(rows) - 1)
    if n_samples > 5:  # 5 人时模板原 height 已够
        try:
            original_h = float(_com_get(shp, "Height", 0))
            new_h = original_h * (n_samples + 1) / 6
            shp.Height = new_h
            print(f"    [TextBox 24] Height 拉长：{original_h:.1f} → {new_h:.1f}（{n_samples} 名样本）")
        except Exception as _e:
            print(f"    [TextBox 24] 拉长 Height 失败: {_e}")
```

**已确认设计选择**：
- 算法：`new_h = original_h × (n+1) / 6`（基线 6 行）→ 5 人时不变，9 人时 ×1.67，12 人时 ×2.17
- 撞下方 shape 不做 boundary check，溢出由人工处理

**实现位置考量**：需要识别"当前正在写哪个 shape"。当前循环里只有 `name` 变量，可以直接判 `if name == "TextBox 24"`。

### 2.5 fallback_map 比例数字动态化（`src/apparel_ppt.py:_build_content`）

`gpt_prompted` 分支里 fallback 字典：

```python
fallback_map = {
    "优点": (
        f"轻薄透气，舒适不闷热（{n}/{n}）\r"
        f"吸湿排汗性能好（{n}/{n}）；\r"
        f"速干性能极好（{n}/{n}）大部分时间都很干爽"
    ),
    "缺点": (
        f"肩部挖空偏小，会勒腋下（部分样本）；\r"
        f"后背开叉偏高（部分样本）；"
    ),
}
```

n 从 `len(rows) - 1` 算。

**注**：fallback 仅 GPT 调用失败时触发，正常运行不显示，但保持字面一致性是健壮性基线。

**已知 trade-off**：原版"优点"末句是 `（1/4）大部分时间都很干爽`，含"少数体验"层次；
新版三句全 `({n}/{n})` 是为了避免硬编码比例数字，丢了语义层次。fallback 极少触发，
若未来想恢复层次感，可改为 `({n-1}/{n})` 或 `({n//2}/{n})` 等。

## 7. Post-mortem：验证时发现的 Chart 污染 bug（fix3-bonus）

**触发场景**：fix3 跑 mc_gpt='y' 验证时，PPT slide 12 的 Chart 7 / Chart 9（即模板 Chart 12 版型 / Chart 15 面料 的 OLE 替换产物）数据全错：

| 期望 | 实际 |
|--|--|
| 6 个值（版型【整体/领口/袖口/肩部/胸围/腰围】） | **17 个值（4 个 category 全部累加）** |
| XValues = `['整体','领口','袖口','肩部','胸围','腰围']` | XValues = 巨长拼接污染串 |
| series.name = '均值' | series.name = **`'Alisa'`**（问卷第一行某跑者名） |
| IsLinked = False | IsLinked = **True** |

**根因（xlwings 桥接 dump 坐实）**：

```
版型 anchor=A61 期望 2列×7行 → 实际 CurrentRegion = A61:R68 (8行×18列)  💥
面料 anchor=A72 期望 2列×3行 → 实际 CurrentRegion = A72:R74 (3行×18列)  💥
吸湿 anchor=A79 期望 2列×5行 → 实际 CurrentRegion = A79:B83 (5行×2列)   ✓
速干 anchor=A88 期望 2列×5行 → 实际 CurrentRegion = A88:B92 (5行×2列)   ✓
```

第 5.4 模块 questionnaire 跑的时候在 col 3~18 区域留了临时数据，apparel anchor
落点（A61 / A72）虽然自身 2 列干净，但右侧 col B~R 有残留 → `anchor.api.CurrentRegion`
碰不到空列就一路扩张到 col R → `set_source_data` 把 18 列全当 chart 源 →
series.name 取问卷跑者名（"Alisa"）、17 values 全混入。第 3/4 个 anchor 落在 row 79+
脱离了残留区，所以干净。

**修法（双保险）**：

1. **`_prepare_apparel_chart_data` 写入前 `clear_contents()`**：精确清 anchor 的行
   footprint × 右侧 18 列，仅清当前 chart 行段（不影响其他 chart anchor）
2. **`make_chart_for_apparel` 不走 CurrentRegion**：apparel 临时表固定 2 列，行数
   用 `mc_cell.expand("down").last_cell` 探，set_source_data 用明确 range

不在原 fix3 5 项改动里、不算 A/B 级问题（pre-existing chart 路径 bug，新问卷下因
样本 9 人 + 4 个 chart 间距压缩才显现）。代码 diff 集中在 `src/apparel_ppt.py`
`_prepare_apparel_chart_data` 和 `make_chart_for_apparel` 两个函数。

**回归验证脚本**：`debug/_diagnose_chart_anchor.py`（复现 4 个 chart anchor
位置 + CurrentRegion 实况，未来类似问题快速定位用）。

## 8. fix3-bonus-2：透气性列被漏 → category 动态识别重构

**触发**：用户复核新问卷面料 chart 时发现 "3、透气性评分" 没出现在面料 chart 里
（只有 手感/亲肤度 + 轻量化 共 2 项，期望 3 项）。

**根因**：旧版 `_extract_means_for_category` 按 `_CATEGORY_KEYWORDS["面料"] =
["面料","亲肤","轻量"]` 关键词死匹配。新问卷把列名简化成"3、透气性评分"，
不含任何面料关键词 → 被遗漏。这是脆弱启发式（旧问卷叫"2、面料透气性"含"面料"
所以能匹配，新问卷去前缀就漏）。

**修法（更鲁棒的动态识别）**：

利用问卷设计的稳定规律 ——「每个 category 末尾必有"XX评价（文字描述）"列
作 section terminator」。新增 helper `_section_boundary(headers, category)`：
找到含 category 关键词的 terminator，归属"上一个 terminator + 1 ~ 当前
terminator - 1"之间的所有数值列。这样：
- 关键词只用来匹配 4 个 terminator（结构稳定，模板不轻易改）
- 评分列归属由位置决定，**完全不依赖列名字含 category 关键词**

兜底：找不到 terminator 时回退到旧关键词匹配（极端非标准问卷不崩）。

**双 schema 验证**（`debug/_fix3_section_smoke.py`）：

| 问卷 | 版型 | 面料 | 吸湿排汗 | 速干 |
|--|--|--|--|--|
| 新 | 6 ✓ | **3 ✓**（透气性进来了）| 4 ✓ | 4 ✓ |
| 旧 | 5 ✓ | 3 ✓ | 3 ✓ | 3 ✓ |

**附带修正**：`_clean_chart_label` 原本循环剥 `_CATEGORY_KEYWORDS[category]`
全部关键词当 prefix，导致"3、轻量化"被剥成"化"。改为只剥 category 名本身
（如"面料"），不剥辅助识别 keyword（如"亲肤""轻量"）。

## 9. fix3-bonus-3：questionnaire chart 同类污染（src/Function_030.py）

**触发**：apparel slide 12 修好后，用户复核【5.4】questionnaire 分页（每页 2
runner + 2 chart）发现 slide 10/11 chart 数据错乱：

| Slide / Chart 位 | 应显示 | 实际显示 |
|--|--|--|
| 10 #04（恬恬位）| 恬恬评分 17 项 | series.name='**Alisa**', V=Alisa 数据 |
| 10 #07（Alisa 位）| Alisa 评分 17 项 | 同 #04（**两 chart 完全一致**）|
| 11 #04（周敏位）| 周敏评分 | series=['手感/亲肤度' 4.11, '轻量化' 3.89]（=apparel 面料数据）|

**根因（与 apparel chart bug 同源）**：

`make_chart_for_questionnaire`（`Function_030.py:2311-2330`）用 `mc_cell.api.CurrentRegion`
取 source range，跟 apparel `make_chart_for_apparel` 是同一函数模板。当
mc_cell 周围有残留数据（同问卷 sheet 上 apparel 后续会写的 anchor 区域），
CurrentRegion 扩张，set_source_data 抓到错误 range，chart 内部 link 指向错
位置。叠加 OLE linked 特性，后续其他 chart / apparel 写新数据时**还会反向
污染**已经粘贴到 PPT 的 chart 显示（周敏 chart 显示 apparel 面料数据就是
这个机制：周敏 chart link 到的 range 后来被 apparel anchor=A72 覆盖）。

**修法（双保险 + 升级版）**：

1. **set_source_data 用 explicit range**（同 apparel 修法）：i 写死 2（title +
   1 runner），j 用 `mc_cell.expand("right")` 探，不走 CurrentRegion
2. **显式 `ChartData.BreakLink()`**（apparel 没做这步但 questionnaire 必须）：
   chart 粘贴到 PPT 后调 BreakLink 把数据 embed 到 chart 内置 workbook，
   彻底切断与外部 Excel range 的链接，后续 sheet 任何变化都不会再影响 chart。
   注意先 `mc_shape.Item(1)` 拿真 Shape 再访问 `.Chart`（ShapeRange.Chart
   抛 COM 错，apparel fix5 已踩过）

**影响范围**：所有调用 `questionnaire_Excel` 的模板（yzr / zxh / apparel
都走【5.4】），需后续验 yzr/zxh 也不回归。CutCopyMode=False 行为不变（保留）。

## 10. fix3-bonus-4：apparel chart `expand("down")` 多吃 questionnaire 残留

**触发**：bonus-1 修好后用户复核 slide 12 版型 chart，发现 6 个正确 bar 之后
**多出一条 "Alisa: 4"** —— 跑者名变成了 chart bar 标签。

**根因（apparel 自己的修复留了 1 个边界）**：

`make_chart_for_apparel` bonus-1 改用 `mc_cell.expand("down")` 探纵向尺寸（替代
有 bug 的 CurrentRegion），但 `expand("down")` 是 ctrl+down 行为，**遇空 cell
才停**。Excel 数据布局实测：

```
questionnaire mc_cell:  A32, A37, ..., A62, A67, A72   (每 +5 行)
apparel anchor:          A61, A72, A79, A88            (offset 50/61/68/77)

版型 anchor=A61 写 row 61-67 (1 header + 6 data)
　row 67 = questionnaire runner 8 title （会被 apparel clear 清掉）
　row 68 = questionnaire runner 8 data 第一列 = "Alisa"  ← 没被 clear！
　row 69 = 空

expand("down") 从 A61 走 → A67 腰围 → A68 "Alisa" 还有数据 → A69 空才停
→ 多吃 1 行 → set_source_data 抓 A61:B68 = 8 行 → chart 多出 "Alisa: 4" bar
```

**修法**：放弃用 `expand("down")` 推断尺寸（脆弱），让 `_prepare_apparel_chart_data`
显式返回 `n_rows`，caller 透传给 `make_chart_for_apparel`：

- `_prepare_apparel_chart_data` 返回签名改为 `(anchor, n_rows)` tuple
- `make_chart_for_apparel` 新增可选参数 `n_rows=None`：传入时直接用，不传则
  回退 expand（向后兼容）
- caller `make_apparel_slide` 循环里解包并传递

回归 smoke：双 schema 全 PASS（`debug/_fix3_section_smoke.py`），label 干净
（含旧问卷"轻量化"、新问卷"透气性"）。

**通用教训**（写进 [[feedback_com_constraints]] 类经验）：xlwings `expand` 系列
方法是"按 Excel 用户视角"的 ctrl+方向键模拟，**对残留数据敏感**。涉及多个
模块共享同一 sheet 的场景，应该用显式 size 而不是 expand。这也是为什么
`CurrentRegion` / `expand("table")` / `expand("down")` 都不够稳——只要旁边
有任何 stale data 都会污染。

## 11. fix3-bonus-5：questionnaire 入口清残留（治本于源头）

**触发**：bonus-1/3/4 各自修了 chart helper 自身对 expand/CurrentRegion 的依赖
之后，用户提出更彻底的诉求 —— "每次重跑 Main.py，进入问卷处理时先把有效数据
区域外的临时数据清掉"，从源头避免上次跑的残留污染本次跑。

**修法**：`src/Function_030.py` 新增 helper
`_clear_residual_outside_valid_region(mc_sht, mc_cell0)`，`questionnaire_Excel`
入口在 `mc_cell0 = get_range(mc_sht)` 之后立即调用。

**动态识别**（不写死任何 row/col 数字）：
- get_range → 扫描第一个非空 cell（不假设 A1）
- mc_cell0.api.CurrentRegion → 自动扩展到连续数据块（不假设 10 行 / 36 列）
- 清理范围 = used_range - CurrentRegion 的下方 + 右侧部分

**新/旧问卷自适应实测**：
