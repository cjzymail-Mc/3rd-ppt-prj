PPT 受试者信息表单常见两类填错：
- 体重："100 KG" 实为 "100 斤"（=50kg）
- 身高："1 CM" 实为 "1 m"（=100cm）

**为啥单一阈值不够：** 第一版 `weight > 110 → ÷2` 漏掉了 100 这种边界值（160cm + 100kg 显然异常但 100 ≤ 110 不触发）。简单降阈值到 80 又会误伤真 80kg 男性。正确解：用 BMI 反推。

**两步归一化套路（apparel_ppt.py::_normalize_person）：**

1. **粗修**：
   - 身高 < 3 → 视为 m，×100 转 cm（1.65 → 165, 1 → 100）
   - 体重 > 110 → 视为斤，÷2 转 kg（130 → 65）

2. **BMI 交叉验证（细修）**：
   - 算 `BMI = w / (h/100)²`
   - 若 BMI ∈ [16, 32] → 接受
   - 否则试 `w/2`，若新 BMI 落入 [16, 32] → 用 ÷2 后的体重
   - 都不行 → 保留粗修结果（数据质量问题，超出自动修复范围）

**测试用例（已通过）：**

| 输入 | 输出 | 备注 |
|---|---|---|
| (160, 100) | (160, 50) | BMI 39 → ÷2 → BMI 19.5 ✓ |
| (180, 90) | (180, 90) | BMI 27.8 ✓ 真胖子不误伤 |
| (170, 130) | (170, 65) | 粗修阶段就解决 |
| (1.65, 52) | (165, 52) | m → cm |
| (1, 100) | (100, 100) | 双错无解，保留 |

**How to apply:**

- 任何含身高/体重的用户填表场景都可复用这套逻辑，模式通用：先按"明显单位错"粗修，再用业务领域知识（BMI）做合理性兜底。
- prompt builder 和 fallback **都要先洗再喂下游**，否则 GPT 拿到脏数据会乱编（GPT 对 100kg 不会觉得有问题）。
- BMI 区间 [16, 32] 比标准 [18.5, 25] 宽，留容差给略瘦/略胖的真实值，只挡明显异常。
